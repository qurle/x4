# Configuration

One config system for both firmwares. Owner requirement: *documented configs*.

## Layers

| layer | where | who changes it | survives reboot |
|---|---|---|---|
| **Absolute safety limits** | `shared/include/x4/safety.h` (constants) | only a code change + review | – (compile time) |
| **Compile-time defaults** + ranges + docs | `shared/include/x4/config_schema.def` (single source of truth) | edit the file, rebuild | – |
| **Runtime overrides** | NVS namespace `x4cfg` on each board | web page / `POST /config` (Core), `GET /settings?k=v` (camera) | yes |
| **Camera options pushed by the Core** | `POST /register` response `config` | the Core, at every camera registration | no (re-sent) |
| **Secrets** | `core/include/secrets.h`, `camera/include/secrets.h` (gitignored; copy the `.example`) | you | – |
| **Board pins** | `core/include/board_pins.h`, `camera/include/cam_pins.h` | code change | – |

There is no separate `config.h.example`: the schema file *is* the documented default config, and
the secrets have their own example files.

## Rules

- Every option has a name (≤ 15 chars, it is the NVS key), default, min, max, unit, scope
  (core/cam/both), flags and a description. All of that is in the schema line.
- Out-of-range values are **clamped** and logged:
  `lvl=WARN mod=cfg evt=clamped err=500 err_name=CFG_CLAMPED key=ap_max_clients requested=2 applied=6 reason=below_min`.
- **Safety-limited options can only be tightened at runtime** (`SAFE_MAX`: may only go down from
  the compiled default; `SAFE_MIN`: may only go up). Example: `flash_pulse_ms` 100 → 60 is
  accepted, 100 → 140 is clamped back to 100 with `reason=safety_tighten_only`. To loosen one you
  must change the compiled default (and it still cannot cross `safety.h`).
- Config is **validated at boot** (NVS values go through the same rules) and clamped values are
  written back.
- Config is **versioned** (`kConfigVersion` in `config.h`, NVS key `cfgver`). A version change runs
  `migrate()` and logs `err=501 CFG_MIGRATED`.
- The active config is printed at boot (`mod=cfg evt=summary part=N …`) and served at
  `GET /config` (Core, with metadata) and inside `GET /info` (camera).
- `REBOOT` options take effect after a reboot (web page shows ↻).

## Changing options

Web page (`http://192.168.4.1/`, *Config* card): edit a value, it is applied, persisted and the
field turns green (or amber if it was clamped). From a shell:
```bash
curl -X POST "http://192.168.4.1/config?xfer_parallel=1&trig_lead_ms=150"
```
Camera directly (rarely needed; the Core pushes camera options at registration):
```bash
curl "http://192.168.4.50/settings?cam_vflip=1"
```
Change a camera's id without reflashing (reboot to apply):
```bash
curl "http://192.168.4.50/settings?cam_id=3"
```

## Adding an option

1. Add a line to `shared/include/x4/config_schema.def` (keep the column layout).
2. Use it as `conf::get().my_option` (Core) or `x4cam::conf::get().my_option` (camera).
3. If it must take effect live, handle it in `applyLiveConfig()` (`core/src/app/app.cpp`).
4. Run `python tools/gen_docs.py` (CI fails if this table is stale) and `pio test -e native`
   (the schema has compile-time checks for name length and default-in-range).
